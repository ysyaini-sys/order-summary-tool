# 个人工作站稳定基础设计

## 目标

第一阶段只提升 `order-summary-tool` 的稳定性、可验证性和协作安全，不改变订单汇总、快手解密或千川分析的业务口径。

## 成功标准

1. 首页和千川页面的关键入口有自动化冒烟检查。
2. “一键下载”仍使用本机 Automa 的 `toufang` 标识，并在页面上明确显示触发状态。
3. 页面显示工作站版本和更新日期，便于确认 GitHub Pages 是否已发布最新版本。
4. GitHub Actions 能运行完整的 Node 测试套件。
5. 不引入后端、抓取、账号权限、打包工具或新的业务依赖。
6. 不处理此前搁置的订单汇总结果与飞书表格不一致问题。

## 约束

- 继续使用 GitHub Pages 静态部署。
- Excel、CSV、密码和解密过程继续只在浏览器本地处理。
- 保持现有文件入口和业务函数名称，避免大范围重写。
- 本阶段不把本机 Automa JSON 纳入仓库；仓库只记录 `toufang` 接口约定和验收要求。
- 所有改动在独立分支完成，通过 PR 进入 `main`。

## 设计

### 1. 页面版本信息

在首页和千川页面增加同一份轻量版本元数据：

- 工作站版本号：`2026.09.28`
- 页面构建标识：由页面静态常量提供
- 更新日期：显示在页面底部或工作区状态区域

版本信息只用于识别发布版本，不参与业务计算。

### 2. Automa 触发状态

保留首页现有事件：

```js
window.dispatchEvent(new CustomEvent('automa:execute-workflow', {
  detail: { publicId: 'toufang' }
}))
```

在按钮附近增加状态反馈：

- 点击后：`正在调用本机下载工作流…`
- 触发完成：`已发送给 Automa，请等待下载`
- 捕获异常：`未能触发，请确认 Automa 中只有一个 toufang 工作流`

不在网页中猜测 Automa 是否真的完成下载；网页只报告事件是否成功发出。

### 3. 首页冒烟测试

增加不依赖真实 Excel、真实账号或浏览器登录的静态检查，验证：

- `index.html` 包含四个平台入口和一键下载按钮；
- `automa:execute-workflow` 事件仍使用 `publicId: 'toufang'`；
- 订单核心处理函数和快手解密入口仍存在；
- 千川入口仍链接到 `qianchuan.html`。

这些检查用于防止豆包整页替换时误删关键入口，不替代真实文件处理测试。

### 4. Playwright 页面验证

在本阶段加入最小的本地页面验证说明和可执行入口，优先验证静态页面加载、导航和按钮存在性。真实账号、真实下载和加密文件仍由人工验收，不在 CI 中执行。

### 5. 验收

- `node --test tests/*.test.js` 全部通过；
- GitHub Actions 的 `test` 检查通过；
- GitHub Pages 首页可打开；
- 点击“一键下载”后能看到状态提示；
- 千川入口、订单上传入口和快手上传入口仍存在；
- 页面不包含秘密、账号、样例订单或本机绝对路径。

## 不在本阶段处理

- 订单与飞书表格结果差异；
- 千川分析算法和指标口径；
- 快手解密算法；
- Automa 工作流 JSON 的仓库化；
- 后端、数据库、用户登录和在线存储；
- 大规模 CSS 拆分或框架迁移。
