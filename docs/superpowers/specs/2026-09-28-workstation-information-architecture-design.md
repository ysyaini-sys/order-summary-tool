# 个人电商工作站信息架构设计

## 目标

把现有静态工具整理为三个独立、可直接使用的工作区：

1. 订单汇总
2. 投放数据汇总
3. 千川商品分析

页面不再出现重复的品牌栏、大幅宣传标题或重复的页内工作区标签。用户通过左侧导航在工作区之间切换；每个工作区只展示完成该项业务所需的内容。

## 已确认的需求

- 导航放在左侧。
- 快手订单属于订单汇总中的一个平台，不单独成为导航项。
- 投放数据汇总与订单汇总的计算口径、导入和导出完全独立。
- 千川分析从左侧导航打开独立页面（新标签页），避免在订单页面中混入分析界面。
- 保持本地文件读取、浏览器内计算，不增加后端、抓取、账号登录或文件上传服务器。
- 保留现有订单、快手解密、投放和千川的业务计算逻辑；本次不处理“订单汇总与飞书表格结果不一致”问题。
- 不使用虚构的趋势、环比、KPI 或装饰性大标题。

## 页面结构

```
左侧导航
├── 订单汇总       → index.html
├── 投放数据汇总   → toufang.html
└── 千川商品分析   → qianchuan.html（新标签页）
```

所有页面使用同一套窄左栏和内容区布局，但不共享业务表单、结果区或计算状态。

### 订单汇总

页面主体依次为：

1. 标题“订单汇总”和简短说明。
2. 抖音、视频号、快手三个上传卡片。
3. 快手密码输入只保留在快手卡片内。
4. 开始汇总、结果预览、下载和在线表格入口。

不再显示“数据工作台”品牌栏、巨幅“电商数据工作台”标题，或重复的工作区页签。

### 投放数据汇总

这是单独的业务页面，不复用订单汇总的结果表或计算方式。页面主体依次为：

1. 标题“投放数据汇总”和日期范围。
2. 平台选择（全部平台或单个平台）。
3. 各平台投放报表上传区。
4. 单独的开始汇总、投放结果预览和导出。

计算内容限定为投放数据中的消耗、成交金额、订单量、ROI、转化成本等可从文件中得到的指标。平台字段通过表头识别，不能识别时给出明确提示。

### 千川商品分析

保留现有独立分析页和 `qianchuan.js` 的规则。左侧导航中的链接以新标签页打开；页面内部仅保留导入、筛选、报告、导出相关界面，不回到订单或投放表单。

## 视觉规则

- 参考 Apple 官网的克制感：浅灰背景、白色内容卡、深色正文、单一蓝色操作色。
- 去除银灰波纹大横幅、宣传文案和重复导航。
- 以内容层级、留白和卡片边界建立视觉秩序，避免大面积装饰。
- 桌面端左栏固定，窄屏时收起为顶部菜单或抽屉，不遮挡上传和结果区。
- 保留清晰的键盘焦点、状态文案和错误提示。

## 技术边界

建议新增共享的 `workspace.css`，仅负责左栏、页面容器、按钮、卡片和响应式规则。业务脚本继续留在各自页面或现有 `qianchuan.js` 中，不能把三类计算重新合并到一个脚本。

| 文件 | 职责 |
| --- | --- |
| `index.html` | 订单汇总页面及现有订单业务脚本 |
| `toufang.html` | 独立投放汇总页面及投放业务脚本 |
| `qianchuan.html` | 独立千川分析页面布局 |
| `qianchuan.js` | 千川读取、分析、筛选、报告导出 |
| `workspace.css` | 三个页面共用的布局与视觉规范 |
| `tests/` | 现有计算规则与页面结构回归检查 |

## 数据流

```
本地 Excel / CSV
  ↓
对应工作区的文件选择
  ↓
对应页面的解析与计算
  ↓
页面预览 / 导出
```

三个工作区不共享上传文件、结果数据或汇总口径。原始文件与快手密码都不上传，也不写入 GitHub。

## 验收标准

- 左侧导航中只有订单汇总、投放数据汇总、千川商品分析三项。
- 订单页不出现大幅“电商数据工作台”、重复页签或投放汇总内容。
- 快手订单只作为订单页卡片，不是独立导航。
- 投放页可独立选择文件、日期和平台，并生成自己的结果与导出。
- 千川从导航以独立标签页打开，现有导入、筛选、报告导出可用。
- 现有订单与千川测试继续通过；增加页面结构测试，防止重复导航重新出现。
- GitHub Pages 从 `main` 发布，所有改动先通过独立分支 PR 供用户预览。

## 不在本次范围

- 订单汇总与飞书表格结果差异。
- 新的自动下载、爬取、后端服务或账号授权。
- 替换用户电脑中的 Automa 工作流。
