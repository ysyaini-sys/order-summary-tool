# 工作站与网站架构

## 工作站角色

- Mac：本地数据处理、代码编辑、预览和备份。
- Codex：主架构、核心业务逻辑、测试、故障修复和发布准备。
- 豆包：视觉、页面样式和经过确认的局部界面修改。
- GitHub：代码唯一来源、分支隔离、PR 审核和历史回退。
- GitHub Pages：只发布 `main` 分支的正式版本。

## 数据流

```text
本地 Excel/CSV
      ↓
左侧导航选择对应工作区
      ↓
订单 / 投放 / 千川各自的文件选择与解析逻辑
      ↓
各自浏览器内存中的分析结果
      ↓
页面预览 / 下载 / 在线表格
```

原始文件和密码不上传服务器，也不提交到 GitHub。

内容中心是旁路工作区：Profile 保存品牌/账号约束，Project 保存独立的六阶段内容流程、来源索引和版本化产物。数据留在本机仓库目录下的 `profiles/`、`projects/`；`.gitignore` 忽略非示例运行数据。旧商品详情页 checkpoint 可映射到通用流程继续，不要求迁移或删除原数据。

内容阶段为 `发现 → 策划 → 生产 → 审核 → 发布准备 → 复盘`。Skill 清单覆盖选品/趋势整理、策划、短视频、直播、详情页、社媒文案、素材审核、发布准备和复盘。发布准备只生成用户可检查的内容与清单；平台登录、发布、投放、通知和账号变更仍由用户手动完成。商品详情页保留原独立入口，只是生产阶段的一种 Skill。

订单汇总、投放数据汇总和千川商品分析不共享上传文件、结果数据或计算口径。快手订单是订单汇总内的平台卡片；千川分析以独立标签页打开。

## AI 接入边界

AI 是按需的只读解读层，不接管订单、投放或千川计算：

```text
本地文件 → 浏览器原有业务计算 → 页面显示汇总
                                  ↓ 用户主动点击
                         仅发送受限汇总指标
                                  ↓
                        本机 AI 服务 → OpenAI 或本机 OpenClaw Gateway
```

AI 连接是可选的。服务只绑定 `127.0.0.1`；OpenClaw 使用 OpenAI-compatible Responses endpoint，token 只从服务端环境变量读取。没有 AI 时，Profile/Project 管理、阶段记录、断点恢复和项目 JSON 导出仍可使用。内容中心只有在用户主动请求时才发送所选 Profile、Project 与当前任务；绝不扫描订单、投放或千川原始文件。

订单解读只发送平台、日期、有效文件数、匹配行数和成交金额；投放解读只发送按平台汇总的消耗、成交、订单、ROI、转化成本与日期；千川解读只发送当前筛选下的商品汇总、匿名账户序号及筛选状态。原始文件、明细、商品/素材身份、源文件名和快手密码不发送。AI 结果以文字显示，不自动回写或执行投放、通知、订单变更。

## 分支流

```text
main  ←  PR  ←  Codex 分支
  ↑
  └──── PR  ←  豆包分支
```

`main` 是唯一正式版本。任何未经过用户测试的改动都不能进入 `main`。
